Status of this page

The evaluation harness is implemented and the protocol below is fixed. Numerical results are reported from a single authoritative run of python -m dermai.evaluate against the held-out validation split. Any cell still showing pending has not yet been filled from that run, and no value should be inferred for it.

4.1

Evaluation protocol

Evaluation is performed on the 15% validation partition described in the method. Three properties of that partition govern how the resulting numbers should be read.

  • Partitioned at lesion level. No physical lesion contributes images to both training and validation, so reported performance is not inflated by near-duplicate leakage.
  • Natural class distribution retained. Oversampling is applied to the training split only. The validation split preserves the true prevalence (including melanocytic nevi at roughly two-thirds of all cases) so metrics reflect the distribution a deployed system would actually meet.
  • No augmentation at evaluation. The validation path performs decode, resize and batch only. No flips, rotations or contrast jitter are applied. 
python -m dermai.evaluate                          # uses ft_best.keras
python -m dermai.evaluate --model checkpoints/lp_best.keras

Emits overall accuracy, a per-class classification report, melanoma recall, and a confusion matrix serialised to outputs/confusion_matrix.npy.

4.2

Primary and secondary endpoints

Primary endpoint

Melanoma recall

TPmel / (TPmel + FNmel)

Of all true melanomas in the validation split, the proportion the model assigned to the melanoma class. This is the endpoint the project optimises, on the epidemiological argument set out in the clinical context: the five-year relative survival gradient from over 99% (localized) to roughly 35% (distant) means a false negative and a false positive are not commensurable errors.

Secondary endpointWhat it capturesWhy it is secondary
Malignant-group recall Sensitivity across mel, bcc and akiec treated as one positive class. Closer to the deployed decision (the tool aggregates these three) but obscures which malignancy was detected.
Macro-averaged F1 Balanced performance across all seven classes, weighting each equally regardless of frequency. Robust to imbalance, but treats a missed dermatofibroma as equivalent to a missed melanoma.
Per-class precision Of cases flagged as class k, the proportion that truly were. Governs false-alarm burden. Matters for usability, not for safety.
Top-2 accuracy Whether the true class appeared among the two highest-probability predictions. Diagnostic of confusion between visually adjacent categories rather than a performance claim.
Overall accuracy Proportion of all validation images classified correctly. Dominated by the majority class; see below.

On the accuracy figure specifically

Melanocytic nevi constitute roughly 66.9% of HAM10000. A degenerate classifier that always predicted nv would therefore score approximately 67% accuracy while detecting no cancer at all. Any accuracy figure quoted for this dataset must be read against that floor, and a figure in the high nineties is far less impressive than it sounds unless accompanied by per-class recall. This project reports accuracy because omitting it would look evasive, not because it is the number that matters.

The cell to examine first

mel → nv. A melanoma classified as an ordinary mole is the most dangerous single error the system can make, because it is also the most reassuring-looking output. It is worth reporting that cell explicitly rather than leaving a reader to locate it in the matrix.

4.6

How these results should and should not be read

  • Validation, not test. The 15% partition guided checkpoint selection through the val_accuracy monitor. Performance measured on the same split that selected the checkpoint is optimistically biased. A truly held-out test set, or external validation on an independent archive such as ISIC or DERM12345, would be required for an unbiased estimate, and is the natural next step for this work.
  • In-distribution only. Every figure reported here is measured on dermoscopic images from the same archive as training. Nothing on this page estimates performance on smartphone photography, on other dermatoscopes, or on populations HAM10000 under-represents.
  • No comparison to clinicians is claimed. Published human-versus-machine comparisons on this task used controlled reader studies with matched image sets. This project ran no reader study, and no statement about relative performance is supported by these results.
  • Single run, no confidence intervals. Results come from one training run at a fixed seed. Repeated runs across seeds would be needed to separate genuine effects from initialisation variance, particularly for the rare classes.
