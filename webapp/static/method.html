2.1

Dataset

Training uses HAM10000 — "Human Against Machine with 10000 training images" — published by Tschandl, Rosendahl and Kittler in Scientific Data (2018). The archive aggregates dermoscopic images from multiple populations and acquisition modalities, and is distributed through the ISIC archive. Ground-truth labels derive from histopathology, follow-up, expert consensus, or in-vivo confocal microscopy.

2.2

Lesion-level partitioning

HAM10000 contains multiple photographs of the same physical lesion, recorded under distinct image_id values that share a common lesion_id. This is the dataset's most consequential structural property, and mishandling it is the most common source of overstated results in the published literature using this archive.

Image-level split — rejected

Shuffling all 10,015 rows and taking 15% for validation places near-duplicate photographs of one lesion on both sides of the boundary. The model is then partly validated on images it has effectively memorised. Reported accuracy rises; genuine generalisation does not.

Lesion-level split — adopted

The set of unique lesion_id values is shuffled under a fixed seed and partitioned 85 / 15. Every image inherits the assignment of its lesion. No physical lesion appears on both sides, so validation measures generalisation to unseen lesions rather than recall of seen pixels. 

lesions = df["lesion_id"].unique()
rng.shuffle(lesions)
val_lesions = set(lesions[: int(len(lesions) * 0.15)])
val_df   = df[ df["lesion_id"].isin(val_lesions)]
train_df = df[~df["lesion_id"].isin(val_lesions)]

Partitioning is performed over lesions, not images — data.py, lesion_level_split().

2.3

Handling a 58:1 class imbalance

Two standard remedies exist for imbalanced classification: reweighting the loss so minority errors count for more, or resampling the data so minority classes appear more often. Both were attempted. Only the second converged.

Negative result — loss reweighting

Keras class_weight was implemented first. At a ratio of 58:1 the implied weight on the rarest class is large enough that its gradient contribution dominates early updates, and training failed to converge. This is reported rather than omitted: it is the empirical justification for the approach that replaced it.

Adopted — bounded oversampling

Rows from minority classes are duplicated until each class reaches 50% of the majority class count. The bound is deliberate: full equalisation would require repeating the 115 dermatofibroma images roughly 58 times each, which invites memorisation of that specific handful of lesions. Half-parity preserves signal without that degree of repetition.

Two properties of the implementation matter for correctness:

  • Applied to the training split only. The validation split retains the natural class distribution. Oversampling validation would fabricate a prevalence the model will never encounter and make every reported metric meaningless.
  • Duplicated rows receive independent augmentation. Because augmentation is applied per-batch after sampling, two copies of the same source image are transformed differently each epoch. The effective inputs differ even though the source pixels repeat.

2.4

Input pipeline

The pipeline is built with tf.data and differs between the training and validation paths only in shuffling and augmentation.

  1. 1

    Shuffle

    Full-buffer shuffle with reshuffling each epoch. Training path only.

  2. 2

    Decode

    JPEG decoded to three channels.

  3. 3

    Resize

    Bilinear resize to 224 × 224, the native input resolution of EfficientNet-B0.

  4. 4

    Batch

    Batch size 32.

  5. 5

    Augment

    Random horizontal and vertical flips, ±10% rotation, ±10% zoom, ±10% contrast. Training path only.

  6. 6

    Prefetch

    Autotuned prefetch to overlap host preprocessing with device compute.

Pixels are deliberately left unnormalised

Images are kept in the raw [0, 255] range rather than scaled to [0, 1]. tf.keras.applications.EfficientNetB0 incorporates its own rescaling and normalisation layer at the input. Normalising in the pipeline would apply that transformation twice, shifting inputs far outside the distribution the pretrained weights expect. The model would still train and still emit confident probabilities — it would simply be worse, silently. The same convention is enforced in the inference server so that deployment and training preprocessing cannot drift apart.

Flip augmentation is chosen with the domain in mind: dermoscopic images have no canonical orientation, so both horizontal and vertical flips are label-preserving. Rotation, zoom and contrast jitter are kept modest, since aggressive colour distortion would corrupt precisely the pigmentation cues that distinguish these categories.

2.5

Architecture

The backbone is EfficientNet-B0 (Tan & Le, 2019), initialised from ImageNet-1k weights with its classification head removed. B0 is the smallest member of the family at roughly 5.3 million parameters — chosen so the full protocol trains inside the session and memory limits of a free Kaggle GPU notebook, which is a reproducibility requirement rather than a performance compromise.

StageComponentRationale
1EfficientNet-B0, include_top=FalsePretrained convolutional feature extractor; the classification head for ImageNet's 1,000 classes is discarded.
2GlobalAveragePooling2DCollapses the spatial feature map to one value per channel. Parameter-free and position-invariant; far less prone to overfitting than flattening into a large dense layer.
3Dropout(0.3)Regularisation against overfitting on a modest, partially oversampled dataset.
4Dense(7, softmax)Produces a probability distribution over the seven diagnostic categories.
 
base = EfficientNetB0(include_top=False, weights="imagenet",
                      input_shape=(224, 224, 3))
base.trainable = False                    # stage 1: linear probing

inputs  = Input(shape=(224, 224, 3))
x       = base(inputs, training=False)    # pin BatchNorm to inference mode
x       = GlobalAveragePooling2D()(x)
x       = Dropout(0.3)(x)
outputs = Dense(7, activation="softmax")(x)

2.6

The two-stage LP-FT protocol

Training follows linear probing then fine-tuning, formalised by Kumar et al. (ICLR 2022). Their central finding is that naive end-to-end fine-tuning can distort pretrained features and underperform out-of-distribution: across ten distribution-shift datasets, fine-tuning averaged 2% higher in-distribution accuracy but 7% lower out-of-distribution accuracy than linear probing alone. The proposed remedy is to combine the two in sequence.

The head is randomly initialised and therefore produces large, uninformative gradients in its first epochs. With the backbone frozen, those gradients cannot reach the ImageNet weights. The head learns to read features that remain exactly as pretrained.

Beginning from a head that already makes sensible predictions, the backbone is released at one tenth the learning rate. Updates are small corrections adapting general visual features to dermoscopic texture, rather than the large corrective steps a randomly initialised head would have demanded.

The model is recompiled between stages. This is not cosmetic: in Keras, compile() binds the optimiser and its internal state to the current set of trainable variables. Changing which variables are trainable without recompiling leaves the optimiser inconsistent with the graph it is meant to update. Recompilation also supplies the new learning rate and resets Adam's moment estimates, which is desirable at a stage boundary.

2.7

Why BatchNormalization stays frozen

This is the most consequential implementation detail in the project and the one most often omitted from transfer-learning tutorials.

A BatchNormalization layer holds two distinct kinds of state. The first is a pair of learnable affine parameters, γ and β, updated by gradient descent. The second is a running estimate of the mean and variance of its inputs, accumulated by moving average during training and used at inference. Only the first is governed by backpropagation; the second is updated as a side effect of running the layer in training mode.

Observed failure mode

When the backbone is unfrozen without protecting these layers, the running statistics accumulated over ImageNet are overwritten by statistics computed from HAM10000 batches — batches that are small (32), oversampled, and drawn from a narrow visual domain. Every downstream activation is then rescaled against unstable estimates, and validation loss diverges within a few epochs while training loss continues to fall. The signature is unmistakable once seen.

Two independent mechanisms guard against this:

  1. 1

    base(inputs, training=False) at construction

    Pins the backbone's BatchNorm layers to inference behaviour permanently — they normalise using stored ImageNet statistics regardless of the surrounding training context. This flag controls behaviour, and is independent of trainable, which controls weight updates. Conflating the two is the usual source of confusion.

  2. 2

    Explicit re-freezing after unfreezing

    base.trainable = True releases every layer indiscriminately; the loop that follows sets trainable = False on each BatchNormalization layer specifically, so γ and β are held fixed and the moving statistics are not updated.

base = model.get_layer("efficientnetb0")
base.trainable = True
for layer in base.layers:
    if isinstance(layer, tf.keras.layers.BatchNormalization):
        layer.trainable = False

2.9

Checkpointing under non-persistent sessions

Training was performed in Kaggle notebooks, where sessions terminate on a time limit and the working directory does not survive. A thirty-epoch fine-tuning run cannot be assumed to complete in one sitting, so checkpointing is a functional requirement rather than a convenience.

The stock Keras callbacks could not be used. In the installed version, the checkpoint and learning-rate-schedule path performs a deep copy of callback state that fails on this model, because the wrapped EfficientNet backbone holds references that are not copyable — the run crashes at the first save attempt. Both callbacks were therefore reimplemented.

ResumableCheckpoint

  • Writes both a best and a last model every epoch.
  • Serialises a small JSON state file recording epochs completed, the best monitored value, the current learning rate, and the epoch's logs.
  • Holds scalar state only — nothing that would be deep-copied.
  • On --resume, reloads the last model, restores the learning rate, and continues from the recorded epoch.

SimpleReduceLROnPlateau

  • Monitors validation loss with a minimum-improvement threshold of 1e-4.
  • After 3 epochs without improvement, halves the learning rate.
  • Floors the rate at 1e-6.
  • Tracks only two scalars — best value and wait counter — so it is safe to serialise and restore.

The two-stage structure interacts with this cleanly: fine-tuning initialises from lp_best.keras, so the stages are separate resumable runs rather than one long fragile job.

2.10

Reproducibility

The full pipeline is public and runs on free compute. Paths default to the Kaggle dataset layout and are overridable by environment variable, so the same code executes locally without modification. 

# Stage 1 — linear probing
python -m dermai.train --stage lp

# Stage 2 — fine-tuning, from the best LP checkpoint
python -m dermai.train --stage ft

# Resume either stage after an interrupted session
python -m dermai.train --stage ft --resume

# Evaluate on the held-out validation split
python -m dermai.evaluate
